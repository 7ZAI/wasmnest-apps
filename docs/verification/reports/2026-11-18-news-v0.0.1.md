9. 数据页：自启只读展示；导出 JSON 成功且不含凭据字段
10. 圈子：新建后出现在列表，圈子视图出现同名筛选 chip 且可选中
11. 条目详情（两分支）：有条目时已读 / 收藏 / 复制 / 助手入口都给显性反馈
12. 主屏应用卡指向本应用：应用名与 plugin.json 一致

> E2E 运行前提（本机实测）：宿主必须来自**已注册 news 路由**的平台树；`cargo` 模式由运行器

## 4. 结论

**结论**：未完成

**理由**：

- 核心链路（F-01 / F-02 / F-03 / F-09 / F-12 / F-13 的本地交互面）：自动化部分通过；
  真实抓取（F-04）、合并排序（F-05 / F-06）、已读收藏与复制（F-07 / F-08）、授权源（F-10）、
  调度（F-11）、助手工具面（F-14）、移动真机（F-15）未执行。
- 未通过项：无 `❌`。平台 `check-release-manifest` 红项均为**既有**或**发布期填充**，不计入应用缺陷。
- 未完成项原因：本环境无真实源清单 / 授权源测试凭据 / OpenAI 兼容端点 / Android 真机；
  详情类交互在隔离库（无条目）下只走了空态分支。
- 已知缺口（模板 §4）：打开原文、应用内改自启、移动后端剪贴板、系统通知、助手反向调用、
  事件聚类、正文阅读——均未触发，也未记为缺陷。
- 实现口径差异（模板 §4.1）：激活期不再出网（补抓推迟到界面 `refresh-stale` / 首个 15 分钟节拍），
  验收时按新口径判。
