# Network Config（内网穿透配置中心）端到端功能验证模板

> **模板版本**：v1（2026-11-10）
> **适用对象**：`com.wasmnest.net-config`（`servers/net-config/desktop`）
> **报告用法**：复制到 `docs/verification/reports/<YYYY-MM-DD>-net-config-v<版本>.md`，
> 按 §3 执行；标记口径见 [README.md](README.md) §3.3。
> **定位**：穿透配置的**跨应用唯一真源**——一处导入自建 relay 地址与业务 WAN 注册表。
> 本中心**不**代任何业务 `expose` / `connect` / 签发票据；拨号与模式判定仍由各业务的
> `tunnel:serve` / `tunnel:connect` 权限在宿主侧执行。

## 1. 功能清单

| 编号 | 功能域 | 用户可见内容 | 端 | 验证方式 | 主要前置 |
| --- | --- | --- | --- | --- | --- |
| F-01 | 入口与服务属性 | 主屏「服务」区入口、不进应用网格、系统服务不可卸载 | 桌面 | 自动 + 手动 | 宿主已装配 |
| F-02 | 当前配置 | 已配置 / 未配置 / 读不到 三态；PeerId、本地复算指纹、准入模式、配额、导入时间、来源、地址列表；显式移除 | 桌面 | 自动（三态）+ 手动（成功移除）+ 单测 | 已导入一份合法配置 |
| F-03 | 部署文本 | Compose / Docker / systemd 三形态，对外主机 / 端口 / 版本可改；复制与下载；非法输入显性报错；**不含任何凭据** | 桌面 | 自动（三形态 + 非法）+ 手动（复制/下载） | 剪贴板可用 |
| F-04 | 地址导入 | `print-addrs --json` / 纯文本 / 单条 multiaddr 三形态；版本与协议不匹配、PeerId 非法、含 `/p2p-circuit` 均显性拒绝且不改配置 | 桌面 | 自动（非法不改）+ 手动（成功落盘）+ 单测 | 一份真实 `print-addrs` 输出 |
| F-05 | 连通性探测 | 对**已保存**的中继地址做一次只读探测（TCP + Noise + PeerId 校验 + ping）：可达结论、PeerId 指纹、RTT、检查时间；失败按端口 / 防火墙 / DNS / 身份不符 / 限流给可操作原因 | 桌面 | 自动（禁用与可点锚点）+ 手动（真实点击）+ 单测（成功 / 六类错误 / 限流） | 已导入一份合法 relay 地址；宿主已重打并导出 `host-tunnel.probe-relay`（T19） |
| F-06 | 业务 WAN 注册表 | 按插件 id 的允许外网开关、生效值、最近更新；切换与失败原因可见 | 桌面 | 自动（取值域）+ 手动（切换）+ 单测 | 宿主插件清单可读 |
| F-07 | 加载 / 刷新 / 错误 | 读取中态、错误带原因、重试、不静默清空存储、刷新不残留 loading | 桌面 | 自动（刷新）+ 手动（错误注入） | 可制造命令失败 |
| F-08 | 消费链路（间接） | BedCode 读中心地址、WAN 闸门生效、首启收养迁移、中心不可用时的缓存降级 | 双端 | 手动（间接）+ 单测 | BedCode 双端在线 |
| F-09 | 多任务预览 | 只读摘要：已配置 / 未配置 / 读取失败（损坏不得冒充未配置） | 桌面 | 手动 + 单测 | 宿主预览面 |
| F-10 | 存储健壮性 | 配置损坏只报错、不静默清除；显式移除才删键 | 桌面 | 单测 + 手动（注入坏数据） | 可写插件 KV |

## 3. 验证步骤

### F-01 入口与服务属性（核心）

- [ ] **S-01-01** 回到宿主主屏，查看「服务」区。期望：存在「内网穿透」入口；应用网格中不出现该服务。
- [ ] **S-01-02** 点击入口。期望：落在 `/network`，页面标题与四张卡（当前配置 / 部署 / 导入 / 连通性）+ WAN 注册表渲染完整。
- [ ] **S-01-03** 打开应用管理 `/sys/apps`。期望：出现在系统服务区；无卸载按钮；自启开关可持久化。
- [ ] **S-01-04** 检查是否弹权限审批。期望：仅 `storage`，按内部业务随包信任域处理，不弹网络 / 隧道类审批。

### F-02 当前配置（核心）

- [ ] **S-02-01** 未导入任何配置时查看当前配置卡。期望：显示「未配置」空态；不渲染 PeerId / 地址等摘要字段。
- [ ] **S-02-02** 导入一份合法配置后查看。期望：显示 PeerId、本地复算指纹（并标明与载荷一致）、准入模式、配额、导入时间、来源、地址列表。
- [ ] **S-02-03** 制造存储损坏（写入非法 `network.relay`）。期望：显示读取失败 + 原因；**不**显示成「未配置」；原数据未被清除。
- [ ] **S-02-04** 在已配置态点击「移除」。期望：二次确认后配置清空并回到未配置态；出现「已移除」提示。
- [ ] **S-02-05** 移除后再点刷新。期望：仍是未配置（不被缓存或旧回执复活）。
- [ ] **S-02-06** 检查页面 DOM 与日志。期望：无 token / 凭据明文；指纹与 PeerId 可见但非秘密。

### F-03 部署文本（核心）

- [ ] **S-03-01** 不填对外主机时查看部署卡。期望：显示空态提示，不产出文本。
- [ ] **S-03-02** 填 `relay.example.com` → Compose 形态。期望：文本含镜像仓库、`4001:4001/tcp` 映射与 `--advertise relay.example.com`。
- [ ] **S-03-03** 切换到 Docker / systemd 形态。期望：文本按形态重生成（`docker run` / `install.sh --advertise`），不残留上一形态。
- [ ] **S-03-04** 填入非法主机（如 `/bad`）或越界端口。期望：显性报错，不产出文本。
- [ ] **S-03-05** 点击复制与下载。期望：剪贴板得到全文 / 下载得到 Compose 文件；失败时有可读提示（不静默）。
- [ ] **S-03-06** 通读文本。期望：不含 enrollment token、密码、私钥或任何服务器凭据。

### F-04 地址导入（核心）

- [ ] **S-04-01** 粘贴 `print-addrs --json` 原文导入。期望：成功提示；当前配置摘要出现且指纹与载荷一致。
- [ ] **S-04-02** 粘贴纯文本输出（每行 multiaddr + 元数据）导入。期望：与 JSON 形态等价落盘，来源标记为文本。
- [ ] **S-04-03** 只粘贴一条 `/ip4|dns4/<host>/tcp/<port>/p2p/<peerId>`。期望：可导入；未提供的元数据按空处理，不猜测。
- [ ] **S-04-04** 粘贴非法载荷（乱码 / 版本不匹配 / 控制协议不匹配 / PeerId 非法 / 含 `/p2p-circuit` / 多 relay）。期望：逐类显性拒绝并说明原因，当前配置不变。
- [ ] **S-04-05** 载荷里故意把 `peer_id_sha256` 写错。期望：本地复算不一致即拒绝（不信任载荷自报值）。
- [ ] **S-04-06** 导入成功后重启宿主并刷新。期望：配置仍可读（落插件 KV，不依赖内存）。

### F-05 连通性探测（核心）

- [ ] **S-05-01** 未配置 relay 时查看探测卡。期望：按钮禁用 + 「先导入地址」提示（`relay.probe.empty`）。
- [ ] **S-05-02** 已配置 relay 时查看。期望：按钮**可点**；未点击前不显示任何结果 / 错误，也不显示「宿主未支持」提示；服务器侧 `wasmnest-relay doctor` 命令常驻可复制。
- [ ] **S-05-03** 点击探测（真实网络）。期望：按钮转 loading（重复点击不排队），随后显示可达结论、PeerId、指纹、RTT、握手耗时与检查时间（`checkedAt`）；RTT 缺失时显示「未知」而不是 0 ms。
- [ ] **S-05-04** 负向：把 relay 端口改成关闭端口 / 安全组拦截 / 地址里换一个合法但不同的 PeerId，各点一次。期望：分别显示「不可达」「身份不符」等可操作原因，**不**显示成成功，也不把身份不符说成不可达；错误明细带具体地址。
- [ ] **S-05-05** 导入新地址或移除配置后查看探测卡。期望：上一轮结论被清空（不指代旧配置）；移除后回到「未配置 + 按钮禁用」。
- [ ] **S-05-06** 旧宿主验证（可选，发布前）：用未按新 WIT 重打的宿主加载本应用。期望：插件实例化失败并**点名缺失的原语**（不是「按钮可点但报错」）；记录实际错误文案。

### F-06 业务 WAN 注册表（核心）

- [ ] **S-06-01** 查看注册表。期望：列出宿主动态加载的业务应用（不含本服务与其它服务型 wasm）；每行显示显示名、插件 id、生效开关、最近更新。
- [ ] **S-06-02** 首次切换某个业务。期望：写入显式值并回显；「未登记 = 允许」的生效值口径与后端一致（未登记行显示「允许」）。
- [ ] **S-06-03** 制造策略读取失败。期望：显示错误与原因，不把整表打成「全部禁止」。
- [ ] **S-06-04** 制造策略写入失败（只读存储 / 命令失败）。期望：显性报错，徽标不翻转成假成功。
- [ ] **S-06-05** 对照 BedCode 实际行为（F-08）。期望：BedCode 行关闭后，其下次 `session.tunnel.prepare` 不再带 relay 地址；已有预留不立即撤销（记录实际观察）。

### F-07 加载 / 刷新 / 错误（核心）

- [ ] **S-07-01** 首次打开页面。期望：出现读取中态，随后内容落定；不闪空白也不长期停在 loading。
- [ ] **S-07-02** 点击刷新。期望：重新读取当前配置与注册表；完成后按钮恢复可点，无残留 loading。
- [ ] **S-07-03** 制造 `net-config.relay.get` 失败（无旧数据）。期望：当前配置卡显示错误 + 原因；不冒充未配置。
- [ ] **S-07-04** 制造注册表读取失败。期望：仅注册表区报错；当前配置与部署卡不受影响（跨卡隔离）。
- [ ] **S-07-05** 检查错误文案。期望：含可理解原因，不泄漏内部路径或凭据。

### F-08 消费链路（核心，间接）

- [ ] **S-08-01** 在 BedCode 桌面设备页/设置页查看「中转服务器」只读入口。期望：显示「已移至统一网络设置」与当前来源（中心 / 缓存）并可跳 `/network`。
- [ ] **S-08-02** 在中心导入地址后回到 BedCode 生成配对二维码。期望：`peer` 载荷带中心配置的 `relayAddrs`；无地址时退回 v1 且显性提示仅内网。
- [ ] **S-08-03** 在中心把 BedCode 的 `allowWan` 关闭，再触发一次 `session.tunnel.prepare`。期望：通道配置不含 relay 地址（仅 LAN）；界面区分「未配置地址」与「已配置但关闭外网」。
- [ ] **S-08-04** 停用中心服务后重启 BedCode。期望：使用本地缓存并显示 `source=cache` + 原因；**不**把「读不到」显示成「未配置」。
- [ ] **S-08-05** 在中心清空配置后重启 BedCode。期望：中心明确 `configured:false` 时不使用缓存（不复活用户已删除的配置）。
- [ ] **S-08-06** 全新环境（中心为空 + BedCode 本地有旧配置）启动 BedCode。期望：触发 `relay-adopt` 迁移并成功；迁移失败时有显性状态，不阻断激活。

### F-09 多任务预览（核心）

- [ ] **S-09-01** 宿主多任务层查看本服务预览卡。期望：只显示只读摘要（已配置 / 未配置），无交互控件。
- [ ] **S-09-02** 制造存储损坏后查看预览。期望：显示读取失败，不显示成「尚未导入中转地址」。
- [ ] **S-09-03** 观察预览副作用。期望：只读 `net-config.status`，不写存储、不拨号、不发探测。

### F-10 存储健壮性（核心）

- [ ] **S-10-01** 手工把 `network.relay` 写成非法 JSON。期望：读取报错且原值保留；显式移除后才删键。
- [ ] **S-10-02** 把 `network.wanPolicy` 写成版本不认识的形状。期望：报错并保留数据，不静默重置为空表。
- [ ] **S-10-03** 在两个业务行上连续快速切换。期望：串行写、末态一致；失败行有错误提示。

## 4. 已知缺口（不纳入通过判据）

| 项 | 现状 | 处理 |
| --- | --- | --- |
| 探测的真实拨号点击 | 能力层已用进程内真 relay 覆盖（成功 / 多地址 / 身份不符 / 不可达）；E2E 不点击（会真拨公网且不写真实配置） | 真宿主重打后按 S-05-03 手动目验；结果写入报告 |
| WAN 注册表覆盖面 | 目前只有 BedCode 读中心策略；file-transfer / ai-chatbox / monitor 等行可切换但业务未接入中心闸门 | 接入属后续票（T12 之后）；判据只要求「BedCode 生效 + 界面不冒充已生效」，不要据其它行断言跨网已关闭 |
| 真实宿主 / E2E 实跑 | `host-runtime.lock.json` 的 `artifacts` 为空，`node scripts/e2e.mjs --app net-config` 环境不可用 | 环境可用后补跑；本轮报告按 `⏭` 记录，不得写成通过 |
| 成功导入 / 移除的自动化 | E2E 只喂非法载荷（成功导入会持久改真实配置） | 由单测（Rust + 前端）+ 人工步骤覆盖 |
| 移动端页面 | 移动是纯拨号方，地址随配对载荷携带 | 按裁定不提供统一设置页；F-01..F-10 仅桌面 |
| 部署文本的远端执行 | 本中心只生成文本，不 SSH、不保存服务器凭据 | 执行与验证由用户按 T13 运维手册自行完成 |
