## 3. 验证步骤

### F-01 挂载与四分区（核心）

- [ ] **S-01-01** 从宿主入口打开 News。期望：四分段可见（今日 / 圈子 / 实时 / 收藏），默认落在「今日」；工具栏含刷新、设置。
- [ ] **S-01-02** 冷启动（数据库为空）。期望：今日视图显示「过去 24 小时还没有内容」空态与「去添加源」入口，不显示错误。
- [ ] **S-01-03** 依次切换到圈子 / 实时 / 收藏。期望：切换不丢失滚动位置之外的状态；实时视图顶部有源状态条。
- [ ] **S-01-04** 切换宿主语言 zh-CN / en。期望：四分段、空态、设置文案全部切换。
- [ ] **S-01-05** 桌面窗口缩窄 / 移动小屏。期望：条目卡不重叠，操作按钮不被截断。

### F-02 源管理（核心）

- [ ] **S-02-01** 设置 → 源 → 添加，选择 `rss` 并填写名称与合法地址。期望：保存后出现在列表，状态为「未抓取」。
- [ ] **S-02-02** 填写非法 URL（空、非 http(s)、明显错误域名）。期望：就地校验失败，不落库。
- [ ] **S-02-03** 重复添加同一 URL。期望：提示重复，不产生两条源。
- [ ] **S-02-04** 编辑源的名称 / 权重 / 圈子。期望：保存后列表与视图同步变化。
- [ ] **S-02-05** 停用源后刷新。期望：该源不参与抓取，其历史条目不进入今日视图。
- [ ] **S-02-06** 删除源。期望：确认后源消失，其来源记录一并删除；若条目无其它来源则从视图消失。

### F-03 圈子管理（核心）

- [ ] **S-03-01** 新建圈子并命名。期望：圈子视图出现该圈子，权重默认 1.0。
- [ ] **S-03-02** 将两个源挂入同一圈子。期望：圈子视图只显示这两个源的条目。
- [ ] **S-03-03** 把某源权重从 1.0 调到 2.0 并刷新今日。期望：该源条目排序明确上移（记录前后顺序）。
- [ ] **S-03-04** 删除圈子。期望：其下源回到「未分组」，不丢源、不丢条目。
- [ ] **S-03-05** 空圈子。期望：显示「这个圈子还没有源」空态。

### F-04 抓取与解析（核心，真实网络）

- [ ] **S-04-01** 刷新一个 RSS 源。期望：今日 / 实时出现条目；标题、来源、时间、链接正确。
- [ ] **S-04-02** 刷新 HN 或 Reddit JSON 源。期望：条目数量与站点榜单大体一致；链接可打开。
- [ ] **S-04-03** 刷新 GitHub Trending 榜单页。期望：条目为仓库名与链接；解析失败时明确报错，不显示空。
- [ ] **S-04-04** 添加 YouTube 频道 RSS 并刷新。期望：视频条目带正确标题与发布时间。
- [ ] **S-04-05** 刷新后重启应用 / 宿主。期望：条目仍在，首次抓取时间与来源保持。
- [ ] **S-04-06** 抓取日志。期望：每次抓取有一行记录，含源、时间、耗时、条目数、结果。

### F-05 去重与合并（核心）

- [ ] **S-05-01** 同一源连续刷新两次。期望：条目数不翻倍。
- [ ] **S-05-02** 两个不同源包含同一 URL。期望：今日视图只出现一次，标注来源数 ≥ 2。
- [ ] **S-05-03** 两个源对同一事件但不同 URL。期望：**不合并**（两条都出现），确认没有误合并。
- [ ] **S-05-04** 带 `utm_*` / `fbclid` 的同一链接。期望：归一化后视为同一 URL，不重复。

### F-06 排序与窗口（核心）

- [ ] **S-06-01** 今日视图。期望：只含 24 小时内条目；越新越靠前（同权重下）。
- [ ] **S-06-02** 实时视图。期望：只含 6 小时内条目，按首次抓到时间倒序；顶部显示各源最近抓取时间。
- [ ] **S-06-03** 修改圈子权重后重看今日。期望：排序变化可解释（记录两组顺序）。
- [ ] **S-06-04** 跨源重复条目。期望：来源数多的条目排在同新鲜度的单源条目前。
- [ ] **S-06-05** 把系统时间调到窗口外（或构造数据）。期望：今日为空、实时为空，不残留旧条目。

### F-07 已读与收藏（核心）

- [ ] **S-07-01** 打开一条条目。期望：标记为已读，列表态变化清晰。
- [ ] **S-07-02** 「全部已读」后再刷新。期望：既有条目不重复高亮；新条目仍为未读。
- [ ] **S-07-03** 收藏一条并重启。期望：收藏状态保留，收藏视图 / 过滤器可见该条。
- [ ] **S-07-04** 30 天清理（构造旧数据）。期望：非收藏旧条目被清，收藏保留。

### F-08 复制原文链接（核心）

- [ ] **S-08-01** 桌面点击「复制链接」。期望：系统剪贴板得到完整原文 URL；有成功反馈。
- [ ] **S-08-02** 移动点击「复制链接」。期望：剪贴板写入成功；若无权限或写入失败，出现可选中链接文本的浮层（不静默失败）。
- [ ] **S-08-03** 复制后粘贴到浏览器。期望：能打开原文页面。

### F-09 失败可见性（核心，部分需构造）

- [ ] **S-09-01** 添加一个 404 源并刷新。期望：源列表显示 `http.status` 与状态码；连续 3 次后标红。
- [ ] **S-09-02** 添加一个返回 HTML 而非 feed 的地址。期望：报「不是可识别的订阅流」，不显示 0 条为成功。
- [ ] **S-09-03** 拒绝某域名的网络授权（桌面首次弹窗点拒绝）。期望：源显示「未授权访问该域名」+ 重试；不显示为空。
- [ ] **S-09-04** 断网后刷新全部。期望：顶部 banner 汇总失败；应用不崩溃；恢复网络后可重试成功。
- [ ] **S-09-05** 查看抓取记录。期望：失败行含错误分类与状态码；不含凭据明文。

### F-10 授权源（核心，【需凭据】）

- [ ] **S-10-01** 添加 X 实验性源并录入测试凭据。期望：保存成功；凭据显示掩码（末四位或长度）。
- [ ] **S-10-02** 刷新。期望：成功时出现条目；失败时报明确原因（`auth.expired` / `rate.limited` / `parse.*`）。
- [ ] **S-10-03** 使用过期凭据。期望：源标红并提示重新登录；**不**降级成公开抓取、不返回空列表冒充成功。
- [ ] **S-10-04** 检查日志与导出。期望：日志与导出的 JSON 均不含凭据明文。
- [ ] **S-10-05** Instagram 同流程。期望：行为一致；若接口不可用，记录为「实验性源失败」，不记应用缺陷。

### F-11 调度与刷新（核心）

- [ ] **S-11-01** 桌面：保持应用激活，等待 15 分钟（或临时缩短间隔验证）。期望：自动抓取一轮，抓取记录新增。
- [ ] **S-11-02** 桌面：关闭应用卡片（真停用）。期望：定时停止（抓取记录不再增长），界面不显示「正在抓取」。
- [ ] **S-11-03** 桌面：重新打开应用且距上次抓取 > 15 分钟。期望：立即补抓一轮。
- [ ] **S-11-04** 手动刷新连点两次（60 秒内）。期望：第二次被防抖拦截并有提示，不重复请求。
- [ ] **S-11-05** 移动：下拉刷新。期望：抓取并显示结果；应用切后台再回前台触发补抓（记录时间）。
- [ ] **S-11-06** 移动：杀进程后重开。期望：不出现「后台一直在抓」的错误印象；抓取记录只在激活后增长。

### F-12 自启指路（核心）

- [ ] **S-12-01** 桌面设置页查看自启状态。期望：只读展示（开 / 关），附指路文案「主屏 → 系统应用 → News → 自启」。
- [ ] **S-12-02** 桌面按指路在宿主开启自启，重启宿主。期望：News 自动激活，抓取记录增长；应用内状态随之变为「开」。
- [ ] **S-12-03** 移动应用详情开启自启，重启宿主。期望：同桌面表现。
- [ ] **S-12-04** 关闭 UI 里的任何「应用内直接改自启」控件。期望：不存在（只有只读展示与指路）。

### F-13 AI 摘要（核心，【需 Key】）

- [ ] **S-13-01** 默认状态（未配置）。期望：AI 开关关闭；不存在任何后台 AI 请求（抓取记录里无 AI 端点调用）。
- [ ] **S-13-02** 配置端点 / Key / 模型。期望：Key 掩码显示；保存后明示「明文保存在本机」。
- [ ] **S-13-03** 手动为今日前 20 条生成摘要。期望：有进度与结果；失败时逐条或整体报错，不伪造摘要。
- [ ] **S-13-04** 关闭 AI 后再触发。期望：入口不可用或提示先开启，不发请求。
- [ ] **S-13-05** 使用错误 Key。期望：显示鉴权失败；日志不出现 Key 明文。

### F-14 助手工具面（桌面，分支）

- [ ] **S-14-01** 在 `feat/nest-assistant-m1` 宿主里让助手列出应用工具。期望：能看到 `news.*` 四个工具及描述。
- [ ] **S-14-02** 助手调用 `news.today-summary`。期望：返回今日条目数组；字段与 schema 一致。
- [ ] **S-14-03** 助手调用 `news.add-source`（write）。期望：宿主按风险等级要求确认；确认后源出现。
- [ ] **S-14-04** 助手调用 `news.refresh-source`。期望：返回抓取结果计数；失败时错误码可读。
- [ ] **S-14-05** 界面点「用助手抓取」。期望：显示「当前宿主助手未提供该能力」，不发请求、不静默回退。
- [ ] **S-14-06** 在 `uat` 宿主（无助手）打开应用。期望：应用正常工作；工具声明不导致装载失败。

### F-15 移动端运行面（核心，真机）

- [ ] **S-15-01** 从应用列表打开 News。期望：全屏单页，底部分段四段（今日 / 圈子 / 实时 / 收藏）。
- [ ] **S-15-02** 设置二级页按系统返回。期望：回到上一次视图（列表），不直接退出应用。
- [ ] **S-15-03** 下拉刷新与滚动。期望：刷新指示可见；列表可滚动；键盘不遮挡表单。
- [ ] **S-15-04** 首次访问自定义域名。期望：出现宿主授权询问；拒绝后源标红（`net.denied`），接受后可抓取。
- [ ] **S-15-05** 窄屏 / 横屏。期望：三元信息（标题 / 来源 / 时间）不重叠。

## 4. 已知缺口（不纳入通过判据）

| 项 | 现状 | 处理 |
| --- | --- | --- |
| 打开原文 | 插件无打开 URL 能力（桌面命令不在白名单、移动无 SDK 面） | 只验证「复制链接」，不验证跳转 |
| 应用内改自启 | `plugin_set_autostart` 需 host 凭证 | 只验证只读展示与指路 |
| 移动剪贴板 | 移动 SDK 无 `host-clipboard` | 走前端 API；失败回退浮层为通过判据 |
| 通知 | 桌面 `notify` 只是事件、移动需动态权限 | v1 无通知功能，不验证 |
| 助手反向调用 | Nest 无对外 api | 只验证工具面（F-14）与显式不可用 |
| 事件聚类 | v1 不做 | 不验证「同一事件合并」 |
| 正文阅读 | v1 不做 | 不验证全文或图片 |
| 断言性网络依赖 | X / Instagram 私有接口会变 | 失败记 `实验性源`，不记应用缺陷 |
