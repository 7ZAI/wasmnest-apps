# Auth Center 端到端功能验证模板

> **模板版本**：v1（2026-10-26）
> **适用对象**：`com.wasmnest.auth-center`（`servers/auth-center/desktop`）
> **报告用法**：复制到 `docs/verification/reports/<YYYY-MM-DD>-auth-center-v<版本>.md`，
> 按 §3 执行；标记口径见 [README.md](README.md) §3.3。
> **定位**：本机入站连接的**唯一裁决者**（fail-closed）。页面只展示中心就位三态、认证方式、
> 接入应用与入场密钥代次；配对码 / QR、可信设备、连接历史**按裁定不设页面**，
> 由 BedCode / File Transfer 经互调消费。

## 2. 验证准备

- [ ] **P-01** 桌面：`servers/auth-center/desktop` 执行 `pnpm install` + `pnpm run test:run` + `pnpm run build`；期望全绿且构建成功。
- [ ] **P-02** 确认 BedCode 与 File Transfer 已构建并在宿主加载（它们是消费链路的前提）。
- [ ] **P-03** 确认认证中心已注册（或准备一个可制造 `not_ready` / `unknown` 的环境），记录当前状态与属主。
- [ ] **P-04** 准备 BedCode 双端配对环境（见 [bedcode.md](bedcode.md) F-13）；若不做双端，F-08 的配对链路标 `⏭`。
- [ ] **P-05** 准备测试用密钥轮换窗口（轮换会影响入场 token，先确认测试设备可重新配对）。
- [ ] **P-06** 报告中**不得**记录密钥材料、JWT、配对码或完整设备指纹；只记代次与状态。

## 3. 验证步骤

### F-01 入口与服务属性（核心）

- [ ] **S-01-01** 回到宿主主屏，查看「服务」区。期望：存在「认证中心」入口；应用网格中不出现 Auth Center。
- [ ] **S-01-02** 点击入口。期望：打开认证中心页面，显示标题「认证中心」与副标题「本机入站连接的唯一裁决者…」。
- [ ] **S-01-03** 检查是否弹授权窗。期望：作为内部业务服务不弹审批；`auth` / `peer` / `storage` 按随包信任域处理。
- [ ] **S-01-04** 打开应用管理 `/sys/apps`。期望：认证中心出现在系统服务区；不出现卸载按钮。
- [ ] **S-01-05** 查看自启 / 启用开关。期望：系统服务开关在场，自启缺省开；状态可持久化。
- [ ] **S-01-06** 确认接入应用列表不包含认证中心自身。期望：只出现 BedCode / File Transfer，不出现自引用（它是提供方，不是消费方）。

### F-02 就位状态（核心）

- [ ] **S-02-01** 在正常注册状态查看就位状态卡。期望：显示「已就位」；显示在册属主与插件版本；缺失字段显示「—」，不显示空白。
- [ ] **S-02-02** 制造注册失败（或使用未注册环境）。期望：显示「确知未就位」+ 原因；入站连接被拒；页面不冒充已就位。
- [ ] **S-02-03** 制造状态读取失败。期望：显示「读不到状态」+ 原因；与「确知未就位」明确区分，不把读不到写成未就位。
- [ ] **S-02-04** 在读取失败前已有成功数据。期望：保留上次成功数据；错误提示可见但不覆盖成空白。
- [ ] **S-02-05** 点击刷新。期望：重新读取状态；读取中显示加载态；完成后状态与原因更新。
- [ ] **S-02-06** 检查页面用词。期望：三态文案与 i18n 一致（已就位 / 确知未就位 / 读不到状态），没有「未安装」冒充状态。

### F-03 认证方式（核心）

- [ ] **S-03-01** 在已就位状态查看认证方式卡。期望：固定显示四种：配对码、二维码、生物凭证、入场 JWT；每项标记「可用」。
- [ ] **S-03-02** 在未就位状态查看。期望：四项均标记「不可用」，与 fail-closed 一致。
- [ ] **S-03-03** 制造方法列表为空。期望：显示「—」，不伪造四种可用。
- [ ] **S-03-04** 检查卡片是否可配置。期望：只读展示，不提供启用 / 关闭开关（能力由中心与宿主决定）。

### F-04 接入应用（核心）

- [ ] **S-04-01** 查看接入应用卡。期望：显示「2 个接入方」；列出 BedCode 与 File Transfer，以及各自消费的面（设备中心 / 信任 / 历史 / 密钥轮换 / 首连确认）。
- [ ] **S-04-02** 查看运行态徽标。期望：落在已激活 / 已加载（未激活）/ 激活中 / 已降级 / 待授权 / 激活失败 / 已停用 / 未安装 / 状态读不到范围内；与宿主实际状态一致。
- [ ] **S-04-03** 对降级 / 激活失败的接入方查看原因。期望：原因上屏；不显示空徽标。
- [ ] **S-04-04** 制造宿主插件清单读取失败。期望：整列显示「状态读不到」并出现接入应用错误提示；**不**把消费方显示成「未安装」。
- [ ] **S-04-05** 点击刷新。期望：重新读取消费方运行态；不刷新整个页面；不丢密钥 / 状态卡数据。
- [ ] **S-04-06** 卸载 / 停用某个消费方后刷新。期望：状态变为「未安装 / 已停用」；清单条目仍在（静态声明），不消失。
- [ ] **S-04-07** 检查接入应用清单来源。期望：两个消费方来自 `consumers.ts` 静态声明，不是宿主动态发现；新增消费方需改源码（记录边界）。

### F-05 密钥代次与轮换（核心）

- [ ] **S-05-01** 查看密钥卡。期望：显示当前签发代次 `g<n>` 与上一代（无则「无」）；**不显示**任何密钥材料。
- [ ] **S-05-02** 点击轮换。期望：确认后当前代次递增；成功提示「已轮换到 gN」；上一代更新。
- [ ] **S-05-03** 制造轮换失败（密钥环不可用 / 命令失败）。期望：显示错误；代次保持不变；不假报成功。
- [ ] **S-05-04** 轮换后检查页面 DOM 与日志。期望：无密钥明文、无 JWT、无 token；仅代次标识。
- [ ] **S-05-05** 轮换后让 BedCode / File Transfer 重新连接。期望：连接行为与实现口径一致（可能要求重新配对）；记录实际结果，不预设通过。
- [ ] **S-05-06** 点击密钥刷新。期望：重新读取代次；不触发轮换；数据与状态卡一致。

### F-06 加载与错误（核心）

- [ ] **S-06-01** 首次打开页面。期望：显示「读取中…」加载态；随后三块数据依次出现，不闪空白。
- [ ] **S-06-02** 制造状态命令失败且无旧数据。期望：显示读取失败卡 + 重试；不把错误吞成「未就位」。
- [ ] **S-06-03** 制造接入应用命令失败。期望：接入应用区显示错误；状态 / 密钥区不受影响（按实现记录跨卡隔离）。
- [ ] **S-06-04** 点击重试。期望：重新读取；成功后错误消失，数据恢复。
- [ ] **S-06-05** 制造慢响应。期望：加载态保持，按钮不重复触发；页面可操作其余区域。
- [ ] **S-06-06** 检查错误文案。期望：包含可理解原因；不泄漏内部路径、token 或密钥。

### F-07 多任务预览（核心）

- [ ] **S-07-01** 在宿主多任务卡片查看认证中心预览。期望：只显示就位三态摘要；无交互控件。
- [ ] **S-07-02** 制造状态不可读。期望：预览显示对应状态 / 失败文案；宿主超时回退品牌卡（按宿主行为）。
- [ ] **S-07-03** 观察预览副作用。期望：只读一次状态；不写存储、不换发令牌、不触发轮换。
- [ ] **S-07-04** 退出预览后打开主页面。期望：主页面数据与预览一致；无状态污染。

### F-08 消费链路（核心，间接）

- [ ] **S-08-01** 打开 BedCode 设备中心。期望：配对码 / QR 生成、设备列表、连接历史、信任撤销、密钥轮换均可用（经互调消费认证中心）。
- [ ] **S-08-02** 在 BedCode 生成配对码，用移动端完成配对（见 [bedcode.md](bedcode.md) F-13）。期望：配对成功；认证中心页面属主 / 状态不变；消费方运行态正常。
- [ ] **S-08-03** 用未信任设备对 File Transfer 发起首连。期望：信任确认生效；接受后可传输，拒绝后发送方看到原因（见 [file-transfer.md](file-transfer.md) F-03）。
- [ ] **S-08-04** 将认证中心置为未就位（或停用）。期望：BedCode / File Transfer 入站全部被拒（fail-closed）；消费方显示降级 / 错误，不静默回退到旧本地认证。
- [ ] **S-08-05** 恢复认证中心。期望：消费方恢复；无需重启宿主（按实现记录是否需要重连）。
- [ ] **S-08-06** 确认只有认证中心一个注册者。期望：BedCode 不再注册 / 注销认证中心；认证中心页面属主为本插件；无双重裁决。
- [ ] **S-08-07** 用旧版本配对记录连接（升级前已配对设备）。期望：按 D5 旧记录不迁移，需要重新配对；记录实际行为，不记为缺陷。

### F-09 页面边界与只读性（核心）

- [ ] **S-09-01** 在认证中心页面寻找配对码 / 二维码 / 可信设备 / 连接历史入口。期望：均无页面入口（2026-10-25 裁定）；这些能力只在 BedCode / File Transfer 页面。
- [ ] **S-09-02** 检查页面是否提供密钥明文查看 / 导出。期望：没有；只显示代次。
- [ ] **S-09-03** 检查页面是否轮询或订阅事件。期望：按实现为手动刷新 / 单次读取；无 1 秒轮询，不持续写存储。
- [ ] **S-09-04** 检查决策计数 / 配对记录统计卡。期望：原「决策计数」占位已删除；不出现空占位卡。
- [ ] **S-09-05** 关闭再打开页面。期望：重新读取最新状态；不保留过期缓存冒充实时。

## 4. 已知缺口（不纳入通过判据）

| 项                          | 现状                                                               | 处理                                     |
| --------------------------- | ------------------------------------------------------------------ | ---------------------------------------- |
| 密钥轮换 / 错误态           | E2E 不点轮换（会持久改代次、影响后续配对），也不从 UI 强制命令失败 | 轮换与错误态由单测 + 人工覆盖            |
| 配对 / QR / 信任 / 历史页面 | 按裁定不设页面，仅保留命令与互调 API                               | F-09 验证「没有」，不要求补页面          |
| 消费方清单                  | `consumers.ts` 静态声明，不是宿主动态发现                          | 新增消费方需改源码；不在页面动态扩展     |
| 旧配对记录                  | 认证记录库为新库，旧记录不迁移（D5）                               | 升级后旧移动端需重新配对，记录为预期     |
| 轮换后的入场 token          | 轮换可能使旧 token 失效，具体以连接结果为准                        | 不预设「自动续期」；记录实际行为         |
| 密钥材料                    | 页面不显示任何密钥                                                 | 若未来新增导出能力，需安全评审后再补步骤 |
