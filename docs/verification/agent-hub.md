# BedCode · Agent 管理域（原 Agent Hub）端到端功能验证模板

> **模板版本**：v2（2026-11-06；按 [ADR 0002](../adr/0002-agent-hub-merge-into-bedcode.md) 整合后改写）
> **适用对象**：`com.wasmnest.bedcode`（`apps/bedcode/desktop`）的 Agent 管理域 `/agents`；**不再是独立应用**
> **配套模板**：[bedcode.md](bedcode.md) 是应用主模板，本文件是该应用的专项分册，只覆盖六个分区及其与会话域的闭环。
> **报告用法**：发版验证时把本文件 §2 / §3 追加到 `docs/verification/reports/<YYYY-MM-DD>-bedcode-v<版本>.md` 的 §6；
> 仅验本域时可单独归档为 `<YYYY-MM-DD>-bedcode-agents-v<版本>.md`，并在报告头写明「只覆盖 Agent 管理域」。
> 标记口径见 [README.md](README.md) §3.3。
> **判据纪律**：不依赖本机装没装某个 CLI、有没有会话日志、网络通不通——先记录真实前置，
> 再按分支判定；不得把「本机没有该状态」直接记为失败。
> **v2 变更口径**：2026-10-28 ADR 0002 生效——`apps/agent-hub/` 与 `com.wasmnest.agent-hub` 已删除，
> 全域迁入 bedcode（Rust `rust/src/hub/`、前端 `src/agents/`）；命令前缀 `agent-hub.*` → `agent.*`（47 条），
> 事件通道 `plugin:agent-hub:*` → `plugin:bedcode:*`；`e2e/specs/agent-hub.spec.ts` 与 `e2e/pages/agentHub.ts`
> 随应用退役，`node scripts/e2e.mjs --app agent-hub` 不再可用。

## 3. 验证步骤

> 自动化锚点（`data-testid`）真源 = `apps/bedcode/desktop/src/agents/components/`；本域顶层 `hub-view` / `hub-tabs` /
> `hub-tab-*` / `panel-*`，侧栏 `nav-agents`。原 `e2e/pages/agentHub.ts` 已删除，不要再对照。
> 命令面统一 `agent.*`；报告里不要写 `agent-hub.*`。
> 分支条件（已授权 / 已安装 / 有日志）按 P-04 / P-05 的真实状态执行，未出现的控件先确认前置。

### F-01 挂载与分区导航（核心）

- [ ] **S-01-01** 从宿主主屏打开 BedCode，确认默认落地终端会话（`/sessions`）；点击侧栏「Agent 管理」（`nav-agents`）。期望：`hub-view` 渲染，默认选中「概览」，`hub-tabs` 可见。
- [ ] **S-01-02** 确认分区标签共六个且顺序为：概览 / 安装与更新 / Skills / 供应商 / 会话日志 / 使用统计（`hub-tab-overview` / `-install` / `-skills` / `-providers` / `-logs` / `-stats`）；默认选中「概览」。
- [ ] **S-01-03** 依次点击六个分区。期望：每次目标 `panel-*` 可见、`aria-selected` 跟随；前一面板完成退场后不可见。
- [ ] **S-01-04** 从「Agent 管理」切到其他侧栏项再返回（或退出应用重进）。期望：不残留上一分区打开的弹窗 / 两击确认态；分区选中态按实现（KeepAlive 可能保留）记录实际行为，不把「保留」误记为缺陷。
- [ ] **S-01-05** 切换宿主语言（zh-CN ↔ en）后重进。期望：分区与主要文案随语言切换，无硬编码中文残留（专有名词 Skills / Agent Hub 除外）；i18n 已改构建期预编译，切换后若文案不跟随需记为缺陷，不以「需重建产物」解释过去。

### F-02 概览：授权与环境检测（核心）

- [ ] **S-02-01** 在未授权状态进入概览。期望：顶部显示目录授权横幅（`overview-auth`）与「授权」按钮；相关能力入口按未授权态禁用或提示。
- [ ] **S-02-02** 点击授权并选择 CLI 配置目录（`~/.claude` / `~/.codex` / `~/.pi` / opencode 等，按宿主选择器）。期望：授权完成后横幅消失，Skills / 供应商 / 日志等入口解除门控。若已授权：记录状态并直接执行 S-02-03。
- [ ] **S-02-03** 查看环境卡（`overview-env`）。期望：OS / 架构 / 版本 / Shell / Node / npm / pnpm / registry / Python 九项均有值或明确的「未检测到」；点击「重新检测」（`overview-detect`）时期按钮禁用，完成后恢复。
- [ ] **S-02-04** 制造或模拟环境检测失败（例如 PATH 隔离）。期望：显示失败块（`overview-env-unavailable`）与重试入口，且**不**显示 Node 安装入口；重试可恢复。
- [ ] **S-02-05** 触发 npm 源测速（需网络，`overview-speed`）。期望：显示最快源名称、耗时、推荐/官方标签；不可达源显示失败而不是假耗时。推荐 npmmirror 时出现「去安装页」入口（`overview-goto-install`），点击能切到安装与更新分区。
- [ ] **S-02-06** 在离线/测速失败状态重复 S-02-05。期望：失败文案诚实呈现，页面不崩、不显示伪造结果。

### F-03 概览：CLI 卡片（核心）

- [ ] **S-03-01** 查看四张 CLI 卡片。期望：pi / opencode / codex / claude 按此顺序渲染；名称正确；每张卡的状态徽章落在已知取值域（已装 / 已装未初始化 / 未安装 / 探测失败 / 检测失败 / 检测中 / 未检测）。

- [ ] **S-03-03** 若存在双安装（同一 CLI 多个路径）：期望显示双安装警告与路径，逐条标注「Hub 管理 / 外部安装」，外部副本给出可复制的清理命令（无法安全推导时为无命令，需手动处理），卸载按钮按策略隐藏或给原因。

- [ ] **S-03-07** 制造 `agent.list-agents` 失败（或使用无 CLI 的隔离环境）。期望：显示降级横幅（`agent-catalog-degraded`）并回退内置四家目录，页面不空白。

- [ ] **S-03-09** 确认启动。期望：按 (environment, workingDir, command) 复用或新建会话配置 → `session.create { start: true }` → 打开终端窗口 → 跳 `/sessions`，会话列表出现新行且终端有该 agent 的真实输出；失败时 `launch-error` 就地提示，不留半成品会话。
