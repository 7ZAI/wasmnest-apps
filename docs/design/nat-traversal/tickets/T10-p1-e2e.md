## 验收条件

**功能链路（双端 E2E + 真机）**

- [ ] 移动经 relay 打开桌面终端、JWT 登录、WS 断线重连。
- [ ] Wi-Fi 下先走 LAN（不经 relay 数据面）；蜂窝直切 WAN；同网段不可达保持 lan 并给手动入口（三用例）。
- [ ] 首次配对全流程：QR v2 扫码 → 票据首帧 → 配对窗口（仅 `/api/auth/*`）→ 配对成功写信任 → 重建隧道业务可达。
- [ ] 真机跨网（手机蜂窝 ↔ 家庭宽带）目验记录；模拟 relay 的集成用例进 CI。

**安全用例（自动化，缺一不可）**

- [ ] run-* 四条桥接路由对 `peer` 一律 403（不变量 3）。
- [ ] `task-status`/`session-mode`/`terminal-bg` 仅已匹配 peer 可达；未匹配拒绝（不变量 16，§0.4 锁）。
- [ ] 票据一次性 / 过期拒绝，LAN 与 relay 两路径各测（不变量 4）。
- [ ] 未匹配无票据 peer 开业务流被拒；配对态连接白名单外路径 403（不变量 8）。
- [ ] peer face / 本地代理流量不享受环回豁免，加密协商失败可见且无明文回退（不变量 15，双端锁）。
- [ ] 撤销设备后隧道立即失效（不变量 7）。

**收口**

- [ ] `node scripts/e2e-dual.mjs --app bedcode` 全绿；锚点（桌面 `data-testid` / 移动 `mobile-`）与用例同步。
- [ ] `docs/verification/bedcode.md` 验证模板更新穿透场景与判据。
- [ ] 验证结果（命令 + 输出 + 真机记录）归档回本 ticket / 对应 issue。
