# 语音识别的「本地」通道 = 宿主 host-stt 直接推理；本地失败绝不自动上云

**状态**：accepted（2026-11-17，取代 ADR 0007）

## 背景与问题

「本地识别」需要模型与原生推理库，而 wasm 插件有 128 MiB 线性内存 + 燃料硬顶、`cdylib` 也无法链接 native 库。ADR 0007 曾选择「用户自建本地 HTTP 端点」绕开这个限制，但代价是：不是真离线、端点协议不兼容、移动端语义不可用。

平台侧现已提供两个能力域：

- `host-audio`：麦克风采集 + PCM 归一（16 kHz 单声道 S16LE）；
- `host-stt`：宿主侧 whisper.cpp 推理（模型目录 / 会话 / 异步任务 / 结果）。

## 决定

1. **`local` 通道 = `host-stt`**：插件打开 PCM 会话、追加字节、`finalize` 拿宿主任务 id，轮询 `job-status` / `job-result`。wasm 只做调度与结果归一。
2. **输入固定 16 kHz 单声道 S16LE**；本地只接受 16-bit PCM WAV 或裸 PCM，其他容器显性报 `audio-unsupported-local`。容器解码不在本服务 v1。
3. **模型是宿主共享资产**：固定 catalog（base / small / turbo）、SHA-256 校验、HF 主源 + 可配镜像、首用不自动下载、默认 `small`。插件只拿模型 id，不接触路径或下载 URL。
4. **本地失败不回退云端**：`auto` 只在请求开始前选一次通道；本地选中后的任何失败（模型缺失、会话失败、推理失败）原样上报。静默上传音频是安全红线。
5. **权限两域**：`stt:infer`（会话 / 任务 / 模型清单）与 `stt:model`（下载 / 删除 / 导入）。
6. **诊断录音只允许服务页触发**：页面经 `host-audio` 采集并直接喂给 host-stt；互调 API 不暴露「远程开麦」。

## 后果

**正面**：真正的离线识别且零外部依赖；用户无需自装服务；模型校验与生命周期由宿主统一管理；本地/远端切换语义清晰。

**负面 / 已知风险**：

1. **推理在宿主进程内**：whisper.cpp（C++/GGML）崩溃会带走宿主。v1 接受该风险（模型与调用面受控）；后续如需强隔离，可把推理迁到 worker 子进程而不改本契约。
2. **模型体积大**（small ≈ 488 MB），首次使用需显式下载；没有自动下载。
3. **移动端暂不可用**：只接了桌面宿主；lib 引擎保留后端抽象。
4. **真实推理质量与性能尚未用真实音频验证**；v1 的验证面止于编译、单测（MockBackend）与构建。

## 替代方案

- **保留本地 HTTP 端点**：用户负担与协议互操作损失，弃用（ADR 0007）。
- **wasm 内推理**：物理不可能（内存硬顶 + 无法链接 native）。
- **随包 sidecar + 自管模型**：本质与 host-stt 重复，且把模型分发/校验/平台矩阵推到应用层；弃用。
- **本地失败自动上云**：违背隐私红线；只保留显式 `remote-only` 或调用方逐次覆盖 `mode`。
