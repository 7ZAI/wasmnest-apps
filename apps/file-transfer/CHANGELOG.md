# Changelog

本文件记录 **File Transfer**（`com.wasmnest.file-transfer`）的版本变更。桌面与移动端共用同一版本号、同一份 Rust 产物与发布 tag。

- 版本真源：`apps/file-transfer/{desktop,mobile}/plugin.json` 的 `version`，双端必须一致。
- 发布 tag：`file-transfer-v<X.Y.Z>`；发布流程见 [`docs/CI.md`](../../docs/CI.md) §2。
- 结构参考 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)，版本号遵循 [Semantic Versioning](https://semver.org/lang/zh-CN/)。
- 发布时把 `[Unreleased]` 收为 `## [<version>] - <YYYY-MM-DD>`，与版本号、tag 同一批提交。

## [Unreleased]

### 新增

- 跨网状态卡（内网穿透 T23 / P0-2）：设备页顶部集中展示「未配置中继 / 正在连接 /
  中继不可达 / 未启用 / 不支持自动发现 / 被中继拒绝 / 查询失败 / 已就绪（空间内
  N 台设备）」中的当前状态，每态给一个主操作；宿主发现快照新增 status / error /
  relay / updatedAtMs，失败时保留上一份设备列表，超过 60s 未更新提示「状态可能过期」。
- 跨网邀请（内网穿透 T23）：一端「生成邀请」把 relay 端点 + 空间码（缺失时自动生成
  `nest-<8hex>`）打包成 `wasmnest://join/…`，另一端扫码 / 粘贴后先在确认页核对
  空间名、中继、空间码前缀与当前空间设备数，确认才落设置（`relayOrigin=invite`）。
  桌面显示邀请二维码，移动端支持系统分享；空间码可轮换（旧邀请仍能进旧空间，但
  看不到本机）。空间码 / 邀请不写日志，也不进信任表。
- 设备行「发送文件」（内网穿透 T23）：未连接时先连接、成功后才弹文件选择器；
  已连接但非活跃时先切换再发送；移动端发送成功后自动切到「传输」页。
- 中继会合发现（内网穿透 T22）：两端配置同一台中继（可选再填同一个空间码）后，
  跨网设备经 relay 自动出现在「附近设备」，无需扫码或复制连接串；二维码 / 连接串
  降级为「无法共用中继」时的兜底。移动端「我的设备」增加系统分享，双端「添加远程
  设备」增加剪贴板粘贴；桌面二维码提示明确「系统相机不会打开本应用」。
- 应用内检查更新：双端接入宿主 `appUpdate`，`plugin.json` 声明 GitHub Release 更新源。
- 远程设备接入（内网穿透 T12）：双端「添加远程设备」粘贴配对连接串
  `wasmnest://pair/<base64url>` / 纯 JSON（只含 `nodeId` + 多地址 + 可选一次性票据，不含长期密钥）；
  移动端另支持**扫码**（`html5-qrcode`，与粘贴同一解析口径，非法码不打断扫描）；
  手动添加的设备按 nodeId 持久化（`addrs` + `paired`），不参与 mDNS 过期清扫。
- 多地址拨号（`dial-peer-addrs`）：LAN 候选优先、relay 候选仅在显式「尝试外网」或没有 LAN 候选时纳入；
  设备行显示宿主上报的真实传输形态「内网直连 / 外网中继」，断开即清除。
- 中继设置：允许中继（缺省开；关闭只影响拨号候选，**不影响加密**）与「中继提示阈值」（MB，0 = 每次提示）；
  经中继发送前按阈值给一次可取消的「可能较慢」提示，不改变模式判定。

- 「我的设备」自持跨网接入（内网穿透 T21 / issue #27）：宿主 `peer node-info` 提供本机
  nodeId / 设备名 / 可拨地址，`configure-relay` 按插件引用计数建立 relay 预留；页面生成
  `wasmnest://pair/…` 连接串与二维码（桌面），不再依赖 BedCode 生成链接。
- 移动扫码改为多档解码（原生 BarcodeDetector → ZXing 全尺寸 / 降采样 / ROI），替换固定
  `qrbox: 250` 的单次解码；连续 10s 未命中给一条非阻断提示。

### 变更

- 首连确认文案明确「接受并信任」，并说明接受后写入信任表、以后不再询问。
- 设备行连接中文案补充「对方可能需要在弹窗中确认」；桌面顶栏发送入口改为
  「发送到当前设备」，不再暗示只有手机。
- 设置页「版本更新」固定在最后，并在检查前显示当前版本号（取自随包 `plugin.json`）。
- 桌面「我的设备」的 relay 地址真源改为「内网穿透」配置中心（`com.wasmnest.net-config`）：
  页面只读展示 + 跳转配置，不再保留第二份编辑器；中心不可用时回退本机缓存并显性提示。
- 预留随插件生命周期收敛：激活 / 改设置 / 打开「我的设备」幂等 reconcile，停用释放本插件份额；
  `allowWan` 关闭或未配置地址时链接只含 LAN。
- 移动端改为底部导航版界面：探索连接 / 浏览 / 传输 / 设置四入口（默认落「探索连接」），设置走宿主二级页整页跳转；传输页保留四等分分段滑块，支持滑动切换浏览 / 设置。
- 穿透配置迁入设置页：中继配置只读展示（地址脱敏、来源、中继状态、空间码），支持中继配置二维码分享（`wasmnest://relay-config`）、移动端扫码导入与从已连接对端同步；探索面板统一为发现层，设备行提供「内网 / 外网」显式连接入口，不再隐式继承上次传输方式。
- 探索连接页收敛为纯发现层（双端）：移除「添加远程设备」（扫码 / 粘贴）与「我的设备」入口及弹层，设备只来自 mDNS + 中继自动发现；本机身份信息（设备名 / 指纹）迁入双端设置页「我的设备」区块，只读展示。
- 应用图标还原为渐变底版本。

### 修复

- 下载完成「打开所在文件夹」报 `path not found`（2026-11-16）：插件激活期先推 `set-download-dir`、后请求节点启动，宿主装配接收侧时按内置缺省（`Downloads/WasmNest`）覆盖，用户选定的下载目录被丢弃——文件实际落在缺省子目录，历史却按设置页目录拼路径。宿主改为以已推送设置为准（跨仓修复，见 `wasmnest-lib` `peer_engine_receive::startup_config`）。
- 「打开所在文件夹」失败不再静默（双端同口径）：桌面原先只写控制台日志、按钮表现为「点了没反应」，现在统一 toast「打开所在文件夹失败：找不到该文件（可能已被移动、删除，或下载目录已变更）」；未配置下载目录时另给「请先在设置中选择下载目录」提示（不再静默丢弃）。移动端沿用同一句文案（原为「本机没有对应文件」）。
- 节点启动声明固定端口（47613），NodePower 配置构造收敛到单点。服务租约路径（双端生产装配）暂不读取该配置，节点仍由宿主全局默认端口 47613 起；无租约装配（无头 / 测试）才按声明值生效。
- 配对设备重启恢复与连接盖章（T12）。
- 手动设备 endpoint 增加 memo，`allowWan` 关闭后重拨为 LAN-only。
- 发送派发改 FIFO，补齐重试凭证与接收提醒；修复移动端错误文案与设置持久化。
- 桌面远端共享目录列表可滚动。
- Rust 审核修复：载入失败保护、热路径落盘合并、共享根事务性。

### 安全

- i18n 消息改为构建期预编译，移除运行时编译与 CSP `unsafe-eval` 前提（安全审查 #50）。
- 传输加密固定开启（内网 / 中继都强制，UI 无关闭入口）；旧对端不支持加密时显性失败，无明文回退。

## [0.0.1] - 2026-10-27

### 新增

- 设备发现：在线对端自动发现与切换，首连确认建立信任。
- 远程目录浏览与多任务并发传输（并发数可调）。
- 传输队列：暂停 / 恢复 / 断点续传 / 失败重试 / 取消，失败原因明示。
- 共享目录：本地目录挂载（可多个）供对端访问。
- 接收策略：逐批批准 / 自动接受 / 自动拒绝，可设批准超时。
- 可信设备与撤销；信任 / consent 决策经 `servers/auth-center` 互调。
- 传输历史与打开所在文件夹。
- 移动端三页签（传输 / 浏览 / 设备）：浏览共享目录多选下载，手机文件经共享目录上传，长按「保存到…」自选保存位置。
- 桌面 + 移动双端发布，双端加载同一份 wasm 产物；桌面端支持多任务卡片只读预览（`mountPreview`）。
